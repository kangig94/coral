# Export lifetime and conversation restore

**Status**: retention and automatic conversation restore implemented.

`CORAL_JOBS_RETENTION_DAYS` (default 14) governs terminal scratch, whole export directories including `executions/` results and `conversation/` archives, journal progress retention, and validated discharged custody entries from proof time. Terminal location copies compact automatically to their matching terminal event. The coordinator schedules retention after startup serves and every 24 h, with five-minute retries only while a budget-limited backlog remains. Live and unknown jobs stay. A directory unknown to the current journal expires only when the newest mtime of the export directory and its top-level entries, including directories, is older than the cutoff. Eligibility never walks descendants. A deletion admission persists the cutoff in meta so partial cleanup can resume despite changed directory mtimes; top-level content newer than the admitted cutoff keeps the residue. A superseded epoch's independent result proof stays until that epoch is gone. Progress fault diagnostics and causal evidence remain for projection replay and shipped readers. Unknown deletion evidence keeps the subject for a later retry; backend status reports the last outcome and per-owner deletion counts, including reclaimed vacuum pages. Bound custody discharge, whole-entry stage retirement, unchanged boot writes, and automatic historical compaction are implemented; continuations restore the retained conversation before provider activation.

Expired exports lose their preserved provider originals, so archive-backed continuations cannot restore an expired conversation. Coral preserves these originals before removing the native copy from the provider's interactive resume picker.

The job is the conversation identity. Automatic restore verifies the committed archive, then publishes the native file through a hard link before continuation activation. The collision rule preserves an existing native file. The next execution cannot commit while the previous execution still owns settlement or retention work. Restoration respects the settled export lifetime; there is no separate restore command.
