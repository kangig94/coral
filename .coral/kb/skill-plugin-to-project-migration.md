# Plugin Skills Can Migrate to Project-Level via init-project Templates
Promoted: 2026-03-15 | Updated: 2026-03-15
## Rule
When a plugin skill has no dependency on plugin MCP tools or plugin-internal resources, it can be moved from the plugin's `skills/` directory to a project-level `.claude/skills/` generated by `init-project`. Use a distinctive name (not generic like `review`) to avoid namespace collision with other plugins — Claude Code may auto-expand namespaces when project-level and plugin-level skills share a name, potentially shadowing the project-level skill.
## Why
A plugin skill that only reads project-local files (`.claude/agents/`, `.claude/rules/`) and spawns subagents via the `Agent()` tool has no runtime dependency on the plugin. Keeping it in the plugin forces all users to have the plugin installed even when the skill's logic is self-contained. Namespace collisions between plugins using common names like `review` can silently shadow project-level skills.
## Pattern
Right — project-level skill generated by init-project:
```
# Plugin template: skills/init-project/templates/skills/tier-review/SKILL.md
# Output: .claude/skills/tier-review/SKILL.md (in user's project)
# Name: tier-review (distinctive, avoids collision with generic "review")
# No coral: prefix needed — it's a project-local skill
```

Wrong — keeping a self-contained skill in the plugin:
```
# Plugin: skills/review/SKILL.md
# Invoked as: coral:review
# Problem: user can't customize, other plugins with "review" may collide
```
