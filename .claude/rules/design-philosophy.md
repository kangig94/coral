# Design Philosophy

## Core Principles

1. **MCP Protocol Correctness**: Every tool response follows the MCP SDK contract. Tool handlers return `{ content: [{ type: "text", text }], isError }`. Schema validation via Zod runs before any execution logic.

2. **Stdio Safety**: The MCP server communicates over stdio. Never use `console.log` in server code — it corrupts the MCP transport. Use `process.stderr.write` for diagnostics.

3. **Graceful Degradation**: If Codex CLI is unavailable, return a clear error message with installation instructions. If a session file is corrupt, skip it with a warning and continue loading valid sessions.

4. **Atomic Persistence**: Session files are written to `.tmp` then renamed. This prevents partial writes from corrupting session state on crash or timeout.

5. **Node.js ESM Hooks**: Hook scripts are Node.js ESM modules (`.mjs`). They read event JSON from stdin, write `hookSpecificOutput` JSON to stdout when active, and exit 0 on no-op. All hooks fail-open: any unhandled error exits silently to avoid blocking Claude Code.

## Source Structure

| Directory | Contents | Modification Rule |
|-----------|----------|-------------------|
| `src/codex/` | MCP server, schemas, executor, sessions, parser, CLI detection | Core runtime — changes require MCP protocol awareness |
| `src/discuss/` | MCP server, schemas, state machine, session store, transcript | Functional core / imperative shell — pure state functions separate from I/O |
| `src/types.ts` | Shared Codex type definitions (CodexExecResult, SessionEntry, event types) | Interface changes affect all codex modules |
| `src/discuss/types.ts` | Discuss type definitions (DiscussState, AgentState, TranscriptEntry) | Interface changes affect all discuss modules |
| `src/shared/` | Utilities shared by both servers (mcp-utils.ts) | Changes affect both cx and dc servers |
| `agents/` | Agent markdown definitions (Claude-native + Codex delegation + discuss) | Follow agent template structure |
| `skills/` | SKILL.md files for slash commands | Frontmatter must match plugin.json |
| `hooks/` | Hook scripts (`.mjs`) + hooks.json config | Node.js ESM, timeout-safe, fail-open |
| `bridge/` | Bundled output (coral-codex.cjs, coral-discuss.cjs) | Generated by build — do not edit directly |
| `docs/` | Architecture, module docs, guides | Update when architecture or API surface changes. Do not duplicate source artifacts. |

## Module Structure

Dependency direction is strict: `server.ts` is the composition root (wiring only). Lower modules never import from upper modules. See `docs/architecture.md` for the current dependency graph.

The discuss server follows a **Functional Core / Imperative Shell** pattern: `state-machine.ts` contains pure state transitions with zero I/O; `session-store.ts` handles all file I/O and cross-process locking; `server-handlers.ts` orchestrates the two layers.
