# Design Philosophy

## Core Principles

1. **Clean-Slate Ownership**: The rewrite branch does not preserve retired paths, aliases, compatibility shims, or transitional facades for convenience. If ownership moves, the old path is deleted and guarded by invariants.

2. **One Coordinator, Two Authorities**: The coordinator owns live orchestration and recovery. The Journal owns process-like event truth. The Corpus owns KB markdown content. Derived projections and equipment state are rebuildable consumers, not authority.

3. **Functional Core / Imperative Shell**: Domains own pure event vocabulary, reducers, read contracts, and shell-local orchestration. Cross-domain assembly happens only through coordinator composition and explicit owner contracts.

4. **Single Runtime World**: Backend I/O flows through the Runtime ports selected at composition. Domains and coordinator services receive time, storage, paths, process, ids, and env through ports instead of reading ambient state. Port objects are eager constants — `runtime.paths.coral` is composed once at `createRealRuntime(flavor)` and is referentially stable across accesses. Tests that mock `node:os.homedir()` per-test must construct the runtime _after_ the mock is set; do not rely on lazy re-evaluation.

5. **Causal Faults**: Failure truth lives once on the originating stream. Job terminals point with `causeRef`; they do not wrap domain fault payloads. `JobLifecycleFault` is reserved for wrapper-local failures with no originating domain event.

6. **Hooks Stay Self-Contained**: Hook scripts are Node.js ESM modules. They read stdin, emit `hookSpecificOutput` through `writeHookOutput()` (which reshapes it per host), fail open, and never import from `src/`.

7. **No Ambiguity**: Every concept has exactly one canonical home. Two files that "could" hold the same thing — even if currently different — get forgotten with 100% probability in future development, and the more generic-named file absorbs everything. The full naming/subdivision policy lives in [`docs/design-rationale.md`](../../docs/design-rationale.md) §9; the load-bearing rules:
   - **Never create a content-blank file** (`helpers.ts`, `utils.ts`, `shared.ts`, `helper.ts`, `shared-utils.ts`) — names that describe nothing invite "anything that fits" and accumulate unrelated logic. Forbidden by `tests/invariants/architecture-boundary.test.ts`.
   - **`index.ts` and `types.ts` ARE allowed anywhere** — conventional names with clear semantics (entry point, type vocabulary); parent directory provides scope. Discipline is on _content_, not _name_: when either grows large or loses cohesion, MUST split. (Per-file line-count caps were a rewrite-time scaffold and were removed once the rewrite landed; growth discipline now lives in code review.)
   - **Magnet vs registry**: a file holding a _typed-identifier registry_ (HTTP status, POSIX errno, `CoralSetupError` documented codes) is the _correct_ shape for that concept — accumulation is what canonical registries look like. Don't split per-domain just because the codes name domain things. The magnet anti-pattern only applies when content-blank names absorb _unrelated logic_.
   - **Filename honesty**: a file's name must describe what it actually does. A "client" that doesn't talk to a transport, a "main.ts" that isn't the entry point, a redundant scope qualifier inside an already-scoped dir — all violate this. Real fixes from the audit: `cli/command-client.ts` → `dispatch.ts`; `cli/main.ts` → `program.ts`; `cli/read-coral-store.ts` → `read-store.ts`.
   - **Subdivision trigger**: promote an implicit prefix cluster to a subdirectory when ≥4 sibling files share a prefix AND form a cohesive component (each file owns a distinct facet of the same bounded responsibility). Strip the now-redundant prefix; if one file is the orchestrator, name it `<subdir>/index.ts`. 3 files = borderline; 2 files = no.
   - **Domain shape minimum, not template**: the 4 Journal-stream domains share a _minimum_ shape — `events.ts` and `read-queries.ts` at the domain root. Beyond that, each domain adds files to match its own complexity (`projections.ts` when it projects to SQL; `reducer.ts` only when it reconstructs in-memory state like a state machine; `paths.ts` only when it owns filesystem paths). Don't manufacture files just to mirror another domain's shape. Full shape policy in [`docs/design-rationale.md`](../../docs/design-rationale.md) §9.7.
   - **Never split a single concept across two files** unless a cycle physically forces the split, and document the cycle when it does — naming both ends, so the note fails loudly once the cycle is gone. This bullet used to carry a worked example, and it is instructive that the example did not survive being checked: `manifest-types.ts` was said to exist only to break a `kb/contracts.ts ↔ manifest-authority.ts` cycle, and today no file of that name exists, `manifest-authority.ts` no longer imports the type the cycle ran through, and the module is imported as shared type vocabulary by most of the KB. A split justified by a cycle outlives the cycle silently, because nothing fails when the reason evaporates.
   - **Never re-export a foreign module's exports as your own.** `import { X } from 'A'; export { X };` makes the importing module a _second_ canonical home for `X`. Future callers then choose between two paths with no rule to disambiguate, and both paths stay alive forever. A module exports only what it owns. Exception: a directory's `index.ts` may publish that directory's own internal members as the public surface — never another module's. Real example from the audit: `runtime/ports.ts` accumulated a re-export block aliasing nine port primitives from `infra/port-types.ts` — fix is to delete the block; primitives import from `infra/port-types.ts` directly. Rationale and the look-for pattern in [`docs/design-rationale.md`](../../docs/design-rationale.md) §9.5.
   - When you find a content-blank file, redistribute its contents to per-domain modules and add an invariant asserting the file does not return (see `tests/invariants/architecture-boundary.test.ts` for the `infra/paths.ts` precedent).

8. **Canonical Values at Boundaries**: Raw optional or truthy wire fields stop at ingress. Transport, CLI, provider, and persistence adapters may receive `string | undefined | null`, but domain cores should see canonical values: non-empty identifiers/refs, explicit `null`, or explicit patch variants (`preserve | set | clear`). Do not use truthiness to decide the meaning of domain IDs, refs, paths, tokens, or continuity fields. Full rationale and examples live in [`docs/design-rationale.md`](../../docs/design-rationale.md) §11.

9. **Local Abstraction Only When It Names a Real Concept**: Same-file repetition of the same invariant, fallback state, or transition may become an unexported local helper or constant. Do not promote it to a shared helper file, do not export it for convenience, and do not extract a helper merely to hide one line. A single-use helper is acceptable only when its name exposes a domain concept or async boundary that the inline code obscures. Details in [`docs/design-rationale.md`](../../docs/design-rationale.md) §11.

10. **No Durable Shape Change May Make an Older Build Fatal**: Releases only move forward — a bad version is answered by a newer one, never by unreleasing — so the build someone rolls back to is already in the field and its source can no longer be changed. The obligation is therefore on the writer, and it is a property, not a technique: **after this change, a build that meets the new shape must fail softly.** Two mechanisms deliver it, and which one applies is decided by whether you control the reader that will meet the shape.

    **The reader is already shipped — isolate by addressing.** A `version` field inside the payload buys nothing here: the older reader opens the artifact regardless, parses it strictly, and a strict failure on a startup path is a coordinator that does not start. Give the new form an address the older reader's own selector already fails to match — a filename suffix, a key prefix, a directory. `handoffCapsuleV2Schema` was renamed in place while keeping `version: 2`, which made a v0.10.6-v0.10.8 capsule unparseable and the coordinator unbootable; the fix was `provider-1<hash>.handoff.v3.json`, invisible to the older discovery pattern.

    **The reader is yours — make it tolerant, and say what it does with what it skips.** Several artifacts take this route and are correct to: the coordinator discovery record is `.passthrough()` so an unknown field never rejects it; `durable_cli_process.v1` decodes to `null` rather than throwing; a provider-operation saga row this build cannot read is skipped and reported by key. Tolerance is not silence — a skipped row must be visible, and what will not be done to it must be stated.

    Two consequences. A reader must accept only the generations it can decode; matching "any generation" reintroduces the same fatal aimed forward, at the build being rolled back _to_. And the generation needs one owner beside the schema that defines it, with addressing and the current-version pointer **derived** from that owner — three independent copies of the same number is a rollback that breaks the first time one is missed.

    This principle had one recorded exception, and the way it ended is the lesson. `#rewriteOpaqueCapsule` upgraded a V1 capsule in place and wrote V3 bytes at the V1 filename; it was kept because reaching it needed a same-build V1 capsule, which "cannot exist". It was also fatal to its _own_ build's next boot, since discovery re-derives a capsule's canonical path from its version and refuses a mismatch — and that alone condemns it. The reachability claim was then refuted on the ground that every source-mode run shared one fallback `buildSetId`, so the build gate that made the path unreachable was forged rather than sound. **That refutation was wrong when it was written.** Reading as same-build under the shared sentinel takes a _writer_ that also had no provable identity, and no such writer can produce a capsule at all: `writeHandoffCapsuleFile` (`src/provider-proxy/handoff-capsule.ts`) is called only by `installRecoveryCredential` (`src/coordinator/live/provider-proxy/set-authority.ts`), which writes only after a grant is installed on three live roles, and those roles descend from a guardian spawned as the bundled `coral-backend.cjs` (`resolveBackendArtifact` in `src/provider-proxy/role-spawn.ts`) whose first act is `assertConsumingBuild` (`src/provider-proxy/bootstrap-capsule.ts`) — refusing a capsule whose `buildSetId` is not the child's own strictly proven one, and refusing outright when it cannot prove one at all. An older _bundled_ build stamped its injected id, so its V1 never matched the sentinel either. Both ends refuse, so the population was empty. That gate shipped in the same commit as `#rewriteOpaqueCapsule`, carrying the same two refusals it carries now, so it was sound for the whole time it stood accused of being forged. **An unreachable path that violates this principle is a liability, not an exception** — delete it. Deleting it was right, and is better supported than the record claimed: the path was unreachable for a sturdier reason than the one written down. What generalizes is the reviewing rather than the gate — the exception survived on an argument that was restated instead of checked, was then discarded on a counter-argument nobody checked either, and only walking the writer's own call chain settled it. Expect a kept exception's argument to be wrong, and check it against the tree rather than against the last reviewer. That record is inline here because it is the evidence for the sentence above it, and because the tracking entry it used to link to was removed together with the fallback itself. The shared fallback is gone: a boot that cannot prove an embedded identity mints its own `buildSetId`, so no two boots claim the same build. And that fallback was never the source-mode-only path its name suggested — it is reached through `embedded_identity_unavailable`, which `resolveStrictBundleIdentity` (`src/infra/bundle-manifest.ts`) also answers for a bundled build whose four injected constants are present but hold malformed values, so a shipped artifact could reach it too.

11. **Evidence That Does Not Decide Has Its Own Disposition**: Wherever this system observes something it does not own — a process, a durable row someone else wrote, a reply that may not come — there are **three** answers, not two: it is so, it is not so, and _the question could not be answered_. The third is not a weaker form of either other one, and the recurring defect is collapsing it into whichever binary the site already had.

    **Unknown never authorizes finalization, and finalization must cite decisive evidence for the exact obligation it discharges — or an explicit authority empowered to override the uncertainty.** Terminalizing a job, retiring a row, deleting a record, minting a disappearance receipt, and delivering a signal are all finalizations. "A positive observation" is not the bar, in both directions: a binding failure is positively observed and decides nothing about the process behind it, while an operator abandoning known-unobservable work is legitimate without observing anything. What is never the bar is `!== absent` — that is not `=== alive`, and a type admitting three values while a call site tests two is the shape this keeps arriving in.

    **Every hold names what ends it, including what happens when that ends.** Refusing to finalize is correct and incomplete: a fence, quarantine, or retry that no reachable event can clear is a job that never settles and an operator with nothing to do. A bounded retry is not by itself an exit — exhausting it must reach a named successor, not the same hold. So the exit is one of: an event that will arrive, a durable quarantine with a supported retry, or an operator decision through a command **that exists**. "Someone will remove the row" is not an exit unless removing the row is an operation this system offers. Shipped three times on one branch: a superseded row that fenced a job forever, an adopted job whose poller could never conclude, and an unattributable row that held back all recovery with no way to remove it.

    **A refusal is visible as durable status, not only as a log line.** Tolerance is not silence. Whatever was declined — a row skipped, a signal refused, a probe unanswered — carries a current status an operator can read, keyed by the identity it can be acted on with, plus one event per change of that subject. A line logged once scrolls away; a warning re-emitted every attempt is noise that gets filtered.

    **Do not overload one value with two dispositions.** `null` meaning "could be anything" on one field and "could be nothing" on the next, in one returned object, is how a fence that protects everything and a fence that protects nothing became the same expression. Name the third answer; do not encode it as an absence.

    **The disposition lives in the return type, and the argument for it is supplementary.** A judgement whose reasoning lives only in a comment cannot be checked, and a detailed comment can be confidently wrong: two of these shipped on arguments that turned out to be factually false — "a retry finds nothing new" for failures that were transient, and "the key names the job" for rows where the payload named another. So the three answers are distinguishable in the type a caller receives, and the obligations each one discharges are asserted by tests. Write the argument down too, and expect it to be attacked.

    **A boundary may release local ownership of a still-live or not-proven-absent obligation only after the returned disposition names a successor owner and the boundary verifies that owner accepted the obligation; quarantine, retry, logging, and durable status are not ownership transfers.**

    **A hold cannot be returned through a type whose success means "done", and completion cannot precede discharge of every obligation it claims.** This is the clause the other four were missing, and it is where all three defects actually escaped: a refusal was represented honestly and then flowed out through an API whose only successful outcome means ownership was discharged. Startup reported recovery complete while admitting nothing; a settlement committed while the process it was responsible for was never disposed of. If a boundary can refuse, refusal must be a variant of what it returns — not a field beside a success.

    What this does not ask for: a universal `Result` type, or a retry on every path. It asks that each site name which of the three it observed, act only on what it observed or what an authority overrode, and say — in the type — what happens next when it observed nothing.

Key rules:

1. Deleted retired paths stay deleted; do not recreate retired barrels, `src/shared`, `src/client`, or compatibility shims.
2. Lower-level modules do not import entrypoints or composition roots.
3. Cross-domain dependencies must be explicit contracts or coordinator composition, not convenience imports.
4. Domain event schemas, reducers, append validators, and describers are owned by the domain that emits the event.
5. Tests and simulation helpers live under `tests/` or `tools/testing/`, never under production `src/`.
6. Domain state is semantic state, not patch syntax. If callers must distinguish preserve, set, and clear, model that as a command/update variant instead of overloading `undefined`.
7. `return await` is reserved for meaningful async boundaries: `catch` error translation, `finally` cleanup/lock release, or deliberate promise settlement ordering. Otherwise return the promise directly.

## Module Structure

The backend has one composition root; the CLI has its own entry point; plugin skills and hooks invoke CLI surfaces. The coordinator may assemble domain shells and contracts, but domains do not import coordinator implementation modules.

Each domain follows the same shape: event contracts, reducer/projection logic, read contracts, and shell modules for I/O. Shared vocabulary that truly crosses domains lives in a lower owner such as `causality/`, `recovery/`, `runtime/`, `store/`, or `infra/`; otherwise it stays with the domain that owns the behavior.

Cause-ref rendering is deliberately split: `causality/` owns the walk and cycle/missing diagnostics, each domain owns its event describer map, and `read-model/event-describers.ts` composes the default map. Adding a domain fault event means adding a domain event schema and domain describer, not editing a central fault union.
