### Search Architecture: 3-Lane Hybrid Ranking

```
Query
 ├─ [Lane 1] Orama text search (boosted: slug 3x, title 2x, tags 1.5x, body 1x)
 ├─ [Lane 2] Entity graph: seed matching → 1-hop expansion → tag overlap scoring
 └─ [Lane 3] Vector: embed query → DuckDB cosine search → dedup per entry

 └─ RRF Fusion (K=60): text=1.0, vector=1.0, graph=0.22 weight
    └─ Community context enrichment (max 3 communities, min 2 result entries)
```

Verified constants at `src/kb/ops/search.ts:44-53`: `HYBRID_RRF_K=60`, `GRAPH_RRF_WEIGHT=0.22`, `GRAPH_ENTRY_MATCH_WEIGHTS=[1, 0.65, 0.4]`.

### Key Data Flows

**`kb search`**: CLI → HTTP POST `/kb/entries?q=` → `kb-tools.ts` Zod validation → `searchKb()` → Orama lazy init → text search → entity graph expansion → vector search (if configured) → RRF fusion → snippet extraction → community enrichment → response

**`kb read`**: Bare slug cascade: memo → note → community → source → principle (`src/kb/read.ts:148-225`). Prefixed selectors (`sources:`, `communities:`) skip cascade.

**`kb promote`**: Validate → resolve memo → acquire lock → check no collision → bump entrySeq → serialize note → atomic write → index update → delete memo → trigger curate (`src/kb/ops/promote.ts:16-82`)

### Curate Pipeline (Background)

```
schedule() [60s debounce]
  → Git sync (pull)
  → Classification: claim uncurated → batch (100 entries, ~16K tokens) → LLM classify → commit metadata
  → Principle discovery: review classified → LLM propose → serialize principles
  → Community detection: tag co-occurrence graph → Louvain → LLM summaries → write communities
  → Git auto-commit + push
```

Budget gate: pauses at 90% of 5h or 100% of weekly Claude API limits (`scheduler.ts:73-97`). Exponential backoff: 30min base, doubles per failure, max 4hr.

### Vector Store Lifecycle

Snapshot-based: `~/.coral/data/kb/vector/{specId}/{snapshotId}/` with `store.duckdb` + `manifest.json`. Atomic swap via `ACTIVE` pointer. `VectorHandleLifecycle` manages DuckDB native addon with lease counting (concurrent reads, isolated staging writes). Chunking: ~2048-token budget per chunk, split at section headers then paragraphs.

Three providers: Gemini (3072d), OpenAI-compatible (any), local ONNX (nomic-embed-text 768d / bge-m3 1024d).

## Gap Analysis

**Finding flow**: 28 initial → 24 after gates → 22 verified [code: 18, inference: 4, assumption: 0]

### CRITICAL Gaps

| ID | Gap | Evidence |
|----|-----|----------|
| G1 | **In-process-only mutation lock** — `withMutationLock()` is a promise chain (`runtime.ts:903-917` — verified), not a cross-process lock. Multiple backend processes sharing the same KB root would break all atomicity guarantees. | code trace |
| G2 | **No `top_k` upper bound** — `kbSearchSchema` validates `top_k` as `z.number().int().positive().optional()` with no max (`kb-tools.ts:45` — verified). Client can request `top_k=1000000`, causing unbounded Orama widening and vector expansion. | code trace |

### HIGH Gaps

| ID | Gap | Evidence |
|----|-----|----------|
| G3 | **No content size limits** — `kbUpdateSchema.content` (`kb-tools.ts:69`), `kbPromoteSchema.content` (`kb-tools.ts:59`), and `writeMemo` (`memo.ts:31`) accept unbounded strings. Arbitrarily large notes degrade index serialization and search snippeting. | code trace |
| G4 | **Entity graph orphans on delete** — `deleteSource()` (`source-store.ts:95-116`) and `deleteFn()` (`delete.ts:8-29`) remove index entries but leave entity graph relationships and orphaned principles. | code trace (confirmed in Scan S1) |
| G5 | **Vector snapshot accumulation** — `ensureVectorIndex` creates timestamped snapshot directories (`sync.ts:446-449`) but never cleans up previous snapshots. Unbounded disk growth over time. | code trace |
| G6 | **`kb_update` does not trigger curate reclassification** — `update.ts:45-60` calls `recordContentMutation` but does not schedule curate. Changed domain/topic retains stale tags indefinitely. | code trace |

### MEDIUM Gaps

| ID | Gap | Evidence |
|----|-----|----------|
| G7 | **No embedding call batching/timeout** — `ensureVectorIndex` sends all changed chunks in a single batch (`sync.ts:280-308`). Slow/unresponsive provider blocks search indefinitely. | code trace |
| G8 | **No source staging cleanup on startup** — Source import staged files persist as orphans if backend crashes between write and cleanup. Vec-staging has cleanup (`runtime.ts:578`) but source staging does not. | code trace |
| G9 | **Promote race condition messaging** — `existsSync(memoPath)` check at `promote.ts:37` is OUTSIDE the lock (lock at line 41). Concurrent promotes: second holder gets cryptic "Memo file not found" instead of "already promoted". | code trace (verified) |
| G10 | **Memo timestamp collision** — `generateTimestamp()` at `memo.ts:17-29` has per-second resolution (verified: `getSeconds()`, no ms). Same-second writes with same topic produce identical filenames; second overwrites first. | code trace |
| G11 | **No search query length limit** — `kbSearchSchema.query` validates `.min(1)` but no upper bound. Extremely long queries can degrade tokenization and entity graph phrase matching. | code trace |
| G12 | **Orama `threshold: 1` strictness** — `search.ts:691-698` uses strict matching (all tokens must match). Multi-word queries expecting OR semantics produce zero results. | code trace |

### LOW Gaps

| ID | Gap | Evidence |
|----|-----|----------|
| G13 | **No merge-conflict detection for index.json/curate-state.json** — Only `.entity-graph.json` checks for `<<<<<<<` markers (`runtime.ts:545`). Other JSON files can silently corrupt. | code trace |
| G14 | **`importedAt` format not validated** — `kbSourceImportSchema` accepts `importedAt: z.string()` (`kb-tools.ts:88`) with no ISO 8601 check. | code trace |
| G15 | **Entity graph unbounded growth** — Every curate classification can add entities/relationships with no count cap, no GC for zero-reference entities. `buildGraphSearchContext` processes entire graph per search. | inference |

### Open Questions

### Peripheral Findings

- Curate retry backoff counter grows indefinitely (`consecutiveFailures`) but retry delay is capped at 4hr. No circuit breaker for persistent failures.
- PDF converter auto-installs Python 3.12 via `uv` (~2GB download) with no timeout — can hang on restricted networks.
- `writeFileAtomic` assumes `renameSync` is atomic — may not hold on NFS/CIFS. Relevant given WSL2 environment.
